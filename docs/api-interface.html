1. Authentication

ส่งแบบ application/x-www-form-urlencoded ไปยัง auth endpoint ของเว็บนั้น

POST {base_url}/login/token.php

username={username_from_env}
password={password_from_env}
service=moodle_mobile_app

Response สำเร็จ

{
  "token": "<temporary-access-token>",
  "privatetoken": "<optional-private-token>"
}

Response ล้มเหลว

{
  "error": "Invalid login, please try again",
  "errorcode": "invalidlogin"
}
Token มีสิทธิ์เทียบเท่าบัญชีผู้ใช้ ห้าม log, commit หรือส่งกลับไปใน Telegram ใช้ในหน่วยความจำและขอใหม่เมื่อหมดอายุ

2. รูปแบบ REST Call

ทุกฟังก์ชันใช้ endpoint เดียวกัน ต่างกันที่ค่า wsfunction

POST {base_url}/webservice/rest/server.php

wstoken={token}
wsfunction={function_name}
moodlewsrestformat=json
...function_parameters

รูปแบบ error กลาง

{
  "exception": "moodle_exception",
  "errorcode": "...",
  "message": "..."
}

3. Read Interfaces ที่ทดสอบแล้ว

wsfunction Input สำคัญ ใช้ทำอะไร
core_webservice_get_site_info ไม่มี อ่าน user id, รุ่น Moodle และรายชื่อฟังก์ชันที่ token เรียกได้
core_enrol_get_users_courses userid อ่านรายวิชาที่ผู้ใช้ลงทะเบียน
mod_assign_get_assignments courseids[] (optional) อ่าน assignment, เวลาเปิดรับ, deadline และ cutoff
mod_assign_get_submission_status assignid ตรวจว่าส่งแล้วหรือยัง ยังแก้ไขได้หรือไม่ และถูกตรวจหรือยัง
core_calendar_get_calendar_upcoming_view courseid (optional) อ่านกิจกรรมที่กำลังจะมาถึง รวม quiz, attendance และ due event

5. การตีความเป็น Task

เงื่อนไขจาก Moodle สถานะใน Kowalski
status = submitted submitted
status = new และยังไม่ถึง duedate pending
เลย duedate แต่ canedit = true และยังไม่ถึง cutoffdate late_but_open
เลย deadline และแก้ไขไม่ได้ overdue
graded = true graded

ใช้ timezone Asia/Bangkok และเก็บเวลาเดิมเป็น Unix timestamp ก่อนแปลงเป็น ISO 8601 ตอน normalize

6. Adapter Contract

interface CoursePortal {
  authenticate(): Promise<PortalSession>
  listCourses(session): Promise<Course[]>
  listAssignments(session, courseIds?): Promise<Assignment[]>
  getSubmissionStatus(session, assignmentId): Promise<SubmissionStatus>
  listUpcomingEvents(session): Promise<CalendarEvent[]>
}

ให้สร้าง adapter คนละ instance สำหรับ tu_moodle และ cs_courses_web แต่ใช้ implementation เดียวกันได้ เพราะ protocol เป็น Moodle REST เหมือนกัน

ID ในฐานข้อมูลควรเติม namespace เช่น tu_moodle:assign:21997 เพื่อป้องกันเลข ID จากสองเว็บชนกัน

7. ขอบเขตความปลอดภัย

  • อ่าน credential จาก .env เท่านั้น และ commit เฉพาะ .env.example
  • ห้ามบันทึก password, access token, cookie หรือ raw login response ลง log
  • เริ่มจาก read-only functions เท่านั้น ไม่เรียก API ส่งงาน แก้ไฟล์ หรือแก้สถานะ
  • เก็บ raw probe และ session artifacts ไว้ใน scratch/ ซึ่ง Git ignore แล้ว
ตรวจสอบกับระบบจริงเมื่อ 24 กันยายน 2026 · เอกสารนี้ไม่มี credential หรือ access token
